# 需求分析

## 用户需求

### 用户角色

求职者，系统唯一终端用户。

### 功能性需求

系统支持简历上传与解析，支持PDF、DOCX、TXT、MD格式简历上传，自动解析简历内容，生成结构化的简历。系统具备联网背景核验能力，利用工具，检索公司信息、github仓库信息，对比简历自述内容，生成证据卡，标记简历信息状态，包含已验证，矛盾，可疑，无法核验四种状态。每一张证据卡对应简历里的一条陈述内容，保存系统检索到的外部佐证材料。

系统实现AI模拟技术面试能力，面试分为**五个阶段**，开场，项目深挖，原理追问，挑战提问，收尾。系统采用流式输出回答，逐字推送，面试中断后刷新页面可以恢复对话。面试官人设可配置，支持调整面试难度，约束大模型不能编造仓库细节，提问必须引用真实证据。系统可以在面试结束后生成面试评估报告，输出评估报告，报告附带引文来源，给出针对性改进计划。系统提供数据持久化能力，存储用户画像，证据卡，风险标记，完整对话历史，使用MySQL持久化保存，支持回放面试记录。

在现有系统能力基础上，还有多项辅助功能进一步提升模拟面试的实用性。系统可以接入麦克风语音转文字能力，求职者通过口述完成面试作答，不再局限于文字输入，更贴近真实线上技术面试场景。系统可以自动记录面试过程中求职者回答存在缺陷的问题，汇总生成面试错题集，配套提供相关技术知识点参考资料，方便求职者后续针对性复习巩固。系统可以根据本次面试识别出的简历问题，生成简历优化建议，直接针对简历中的不实描述与薄弱环节给出修改方案，帮助求职者完善简历内容。系统支持按照不同岗位类型调整面试侧重点，区分后端开发前端开发算法等岗位，让面试提问更加贴合目标岗位的考察范围。系统还可以支持多人面试官模拟模式，切换多位面试官交替提问的形式，还原企业多轮面试的真实体验。同时增加面试计时功能，为求职者的单次回答设置时间限制，营造真实面试中的时间压力，训练求职者在限定时间内清晰表达技术观点的能力。

### 非功能性需求

1. 系统应当具备良好的可测试性，支持单元测试与会话回放调试。
2. 系统支持流式输出，面试问答可提供实时响应效果。
3. 系统拥有良好的模型兼容性，能够切换不同的大模型服务，并支持单进程部署。
4. 系统具备严格的内容约束能力，在面试过程中可识别虚构项目信息，抑制大模型产生幻觉。

## 业务流程需求

用户上传简历，系统解析简历，生成结构化画像，人工确认画像。后台异步联网检索，对比简历信息，生成证据卡，挑战问题。系统进入模拟面试，用户与AI面试官对话。面试结束，系统生成多维度评估报告与改进建议。

## 技术需求

系统需要实现面试官角色模拟能力，支持五阶段面试流程控制与面试难度切换，并且具备内容防幻觉约束能力。系统需要具备工具调用能力，能够完成**代码仓库信息查询**、项目文档读取、全网信息检索与**网页内容抓取**。系统支持各类文档信息抽取，可对多种格式简历进行文本解析，并提取博客等公开文本信息。系统需要具备会话记忆管理能力，能够长期存储面试档案，包含用户画像、证据卡、风险标记以及短期对话历史。系统需要支持面试会话回放功能，完整留存面试对话记录，方便用户复盘面试过程。系统需要具备评估报告生成能力，面试结束后自动整合面试对话、简历核验结果，输出多维度面试评价内容与针对性求职改进建议。

## 约束与风险

1. 联网检索接口存在调用限额，代码仓库、网页检索接口的访问请求可能受限
2. 网页抓取过程可能遇到反爬机制，无法正常获取博客正文。当简历排版结构复杂时，简历文本解析结果会存在偏差，对后续的核验工作造成影响。
3. 系统在进行公开信息检索时，仅可获取互联网公开可访问内容，无法查询未公开的私密项目资料。
4. 在网络通信不稳定的场景下，系统的实时问答响应会受到影响，中断模拟面试会话。
5. 系统生成的面试评估结果仅作为求职训练参考，不能完全等同于真实企业面试官的评价结论。

## 需求优先级

**必须实现需求：**

+ 包含简历解析
+ 联网证据检索
+ 多阶段面试流程
+ 防幻觉约束
+ 面试报告

**可选实现需求：**

+ 人工确认画像
+ 对话回放
+ 多难度面试
+ 雷达图可视化报告
+ 更多简历格式适配
+ 语音输入
+ 多面试官面试
+ 岗位类型区分
